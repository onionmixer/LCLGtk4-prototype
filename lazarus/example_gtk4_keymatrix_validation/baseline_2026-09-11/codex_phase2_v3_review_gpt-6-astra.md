**v3 still needs corrections before coding**, chiefly to replay retention and GTK pressed-key bookkeeping.

1. **Owned references are valid; replay preserves identity.** `gdk_event_ref` increments the count and returns the same pointer; final unref releases the event’s surface and device references. Holding a key event therefore extends those objects’ lifetimes, but does not replay it or accumulate history—history belongs only to motion/scroll events. See [gdkevents.c:855](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gdk/gdkevents.c:855), [gdkevents.c:139](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gdk/gdkevents.c:139), [gdkevents.c:413](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gdk/gdkevents.c:413), [gdkevents.c:3005](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gdk/gdkevents.c:3005).

   `gdk_display_put_event` explicitly queues `gdk_event_ref(event)`; `_gdk_event_queue_append` stores that pointer without copying. Fcitx’s asynchronous callback passes its retained original event to this API. Pointer identity is therefore correct **while the reference remains in your lookup**. No timestamp fallback is needed; the proposed timestamp/keycode/no-release combination would still misclassify Wayland repeats. See [gdkdisplay.c:490](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gdk/gdkdisplay.c:490), [gdkevents.c:549](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gdk/gdkevents.c:549), [fcitximcontext.cpp:36,486](https://github.com/fcitx/fcitx5-gtk/blob/master/gtk4/fcitximcontext.cpp#L486), [gdkdevice-wayland.c:2236](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gdk/wayland/gdkdevice-wayland.c:2236).

   **Add explicit teardown cleanup**, beyond release/replacement/focus-leave. The wrapper unregisters before native teardown, so subsequent focus callbacks fail their liveness check and cannot release your references. See [gtk4widgets.pas:4890](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/lazarus/lcl/interfaces/gtk4/gtk4widgets.pas:4890).

2. **Your later-`A` example is correct in ordinary sequential dispatch.** The excluded printable press returns False, so it adds **nothing to this capture controller’s table**. Existing stale `A` remains. Its next `A` release emits the capture callback, then finds and removes that single entry and returns handled; bubble cannot deliver another KeyUp. Even a handled later press merely re-adds the same set member. See [gtkeventcontrollerkey.c:120](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkeventcontrollerkey.c:120).

   **Still route stale-only compensation through the normal release dedup logic, delivering once when both keycode and stale-keyval match.** GTK performs lookup/removal *after* your callback; nested event processing during LCL KeyUp can change the table before the outer lookup. Consequently, “GTK will swallow this release” must not replace bubble suppression. Remove the compensation obligation before calling LCL to prevent recursive compensation.

3. **The delegate focus controller covers both cases.** Same-window focus changes synthesize `GTK_CROSSING_FOCUS`; deactivation synthesizes `GTK_CROSSING_ACTIVE` with a null new target. The focus controller processes both and emits `leave` when focus exits its subtree. See [gtkwindow.c:2067](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkwindow.c:2067), [gtkwindow.c:5912](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkwindow.c:5912), [gtkeventcontrollerfocus.c:119](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkeventcontrollerfocus.c:119), [gtkeventcontrollerfocus.c:152](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkeventcontrollerfocus.c:152).

   A subsequently dispatched release uses the **current focus of its event surface’s root**, so the ordinary same-window handoff goes to the new widget. However, do not assume that leave makes further delegate callbacks impossible: focus can return before release, and an event already propagating retains its original widget path. Keep cancellation without synthetic KeyUp, and account for callbacks unwinding after cancellation. See [gtkmain.c:1514](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkmain.c:1514), [gtkmain.c:1863](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkmain.c:1863).

4. **Keep the proposed CN condition exactly:**

   ```pascal
   CNResult := DeliverMessage(Msg, True);
   if AHandled <> nil then
     AHandled^ := (CNResult <> 0) or (Msg.CharCode = VK_UNKNOWN);
   if not CanSendLCLMessage then
     Exit(False);
   ```

   Then retain the existing branch condition including `IsArrowKey`.

   An ordinary KeyPreview handler that leaves the key unchanged does **not** cause a nonzero result by merely running. `DoKeyDownBeforeInterface` falls through to False. A successful shortcut—popup, form/menu/action, or application—can return True without zeroing `CharCode`, and `CNKeyDown` then sets `Message.Result := 1`. Omitting `CNResult <> 0` would let those shortcuts reach GTK. The form uses the inherited `TWinControl` method here. See [wincontrol.inc:5867](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/lazarus/lcl/include/wincontrol.inc:5867), [wincontrol.inc:5883](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/lazarus/lcl/include/wincontrol.inc:5883), [wincontrol.inc:5816](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/lazarus/lcl/include/wincontrol.inc:5816), [wincontrol.inc:7254](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/lazarus/lcl/include/wincontrol.inc:7254), [customform.inc:2615](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/lazarus/lcl/include/customform.inc:2615).

5. **Remaining implementation changes:**

   - **Track GTK’s consumed keyvals independently of the latest hardware-key press.** Example: consumed `Ctrl+Shift+A`, release Shift, consumed autorepeat `Ctrl+a`, then release `a`. Replacing the outstanding entry loses `A`; GTK retains both `A` and `a`, then removes only `a`. v3 never records stale `A`. Likewise, an unconsumed repeat must not erase evidence of an earlier consumed press. Maintain a shadow set reflecting every True press return and GTK’s release removals, surviving focus-leave while the controller survives. See [PLAN:608](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/PLAN_GTK4_KEY_PREDISPATCH.md:608), [PLAN:654](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/PLAN_GTK4_KEY_PREDISPATCH.md:654), [gtkeventcontrollerkey.c:124](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkeventcontrollerkey.c:124).

   - **Separate replay history from outstanding physical presses.** Fcitx processes presses and releases asynchronously. An original release or newer repeat can retire the entry before an older press replay arrives, producing another LCL KeyDown. Releases can themselves replay after their capture delivery. Recognition must therefore cover already-delivered press **and release** objects beyond physical-entry removal, with an explicit retention/retirement policy. The one-event bubble marker cannot supply this history. See [PLAN:666](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/PLAN_GTK4_KEY_PREDISPATCH.md:666), [fcitximcontext.cpp:470,486](https://github.com/fcitx/fcitx5-gtk/blob/master/gtk4/fcitximcontext.cpp#L470).

   - **Re-arm bubble suppression on an unconsumed replay.** v3 clears the marker on the next capture event, then its replay branch returns stored False. If that replay reaches bubble—F3 is a straightforward example—it gets delivered again. Restore suppression before that early return. See [PLAN:669](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/PLAN_GTK4_KEY_PREDISPATCH.md:669), [PLAN:672](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/PLAN_GTK4_KEY_PREDISPATCH.md:672).

   - **Reconcile a consumed press after reentrant focus cancellation.** An OnKeyDown handler can move focus and zero the key while the entry still contains provisional `Consumed=False`. Leave cancels it without recording its keyval; the outer callback subsequently returns True, and GTK adds that keyval *afterward*. A generation mismatch must prevent resurrecting physical tracking, but must not omit this GTK-table obligation. See [PLAN:662](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/PLAN_GTK4_KEY_PREDISPATCH.md:662), [PLAN:671](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/PLAN_GTK4_KEY_PREDISPATCH.md:671), [gtkeventcontrollerkey.c:122](/mnt/STORAGE16T/Workspace_STORAGE16T/LCL_GTK4/gtk-4.6.9/gtk/gtkeventcontrollerkey.c:122).
